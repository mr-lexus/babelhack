# Архитектура Babel Hack 0.7

Windows x64, macOS 14.6+ (ARM64/Intel), Linux x64, Tauri 2, Rust, React 18 / TypeScript / Vite. Звуковой источник — устройство воспроизведения, выбранное через CPAL и платформенный адаптер. Windows: WASAPI; Linux: PulseAudio/PipeWire monitor; macOS: отдельный CoreAudio process tap.

## Поток данных

~~~text
WASAPI / CoreAudio tap / PulseAudio monitor → mono PCM 16 kHz → ограниченный аудиоканал (50 × 40 ms)
  → Deepgram WebSocket (TLS, промежуточные и окончательные результаты)
  → TranscriptReconciler → FIFO собранных фраз (32) + watch последней гипотезы
  → OpenAI Chat Completions stream → Runtime
  → session-state / history-changed → главное окно и субтитры
                                     → локальная история
~~~

Промежуточный оригинал отображается сразу и поступает в предварительный перевод. watch хранит последнюю гипотезу: подтверждённые ASR-пакеты плюс текущий изменяемый хвост. is_final означает устойчивость пакета, а speech_final/UtteranceEnd — паузу, а не готовность предложения. Reconciler объединяет пакеты до границы предложения с небольшим ожиданием продолжения (650 мс) либо существенной паузы (1800 мс). При открытом interim таймер не фиксирует стабильное начало отдельно. Короткие реплики, сокращения и явные продолжения обрабатываются отдельно; это эвристика, не семантический классификатор. Защитный предел длинного монолога — 72 подтверждённых слова или 600 символов на границе ASR-пакета. Сам пакет не режется повторно. Оригинал сохраняется до перевода; повторы речи не удаляются.

OpenAI получает предыдущий контекст, текущую фразу и уже показанный черновик отдельными JSON-полями; словарь включён в системную инструкцию. Поток обновляет текущий перевод, а завершённый ответ попадает в ленту. Отсутствие финального Stop, пустой ответ, обрыв и превышение времени считаются ошибками. Параметр temperature не передаётся.

## Владение и остановка

AppState хранит async mutex активной Session и Arc текущего Runtime. Session владеет аудиозахватом, каналами, сигналом stop и всеми JoinHandle. Рабочая задача перевода выполняет запрос непосредственно; отдельных бесконтрольных задач на каждую фразу нет.

При остановке захват освобождается, Deepgram получает CloseStream, затем STT и переводчик завершаются в пределах общего бюджета 8 секунд. Остаток задач отменяется и ожидается; незавершённые фразы получают отметку об ошибке. Явный выход использует тот же путь; крестик может скрывать окно в трей согласно настройкам.

Пауза освобождает устройство; распознанные фразы могут закончить перевод. Продолжение открывает прежнее устройство заново. Ошибка устройства видна в интерфейсе. Указанное, но отсутствующее устройство не подменяется молча.

## Восстановление и ограничения

Deepgram использует управляемое WebSocket-соединение tokio-tungstenite: таймаут подключения 15 секунд, отправки 2 секунды, KeepAlive каждые 3 секунды. После временного сбоя — до восьми попыток с задержкой 2–16 секунд; длительное успешное соединение сбрасывает счётчик. Ошибки авторизации/параметров завершают подключение. Пропущенный звук не восстанавливается.

Перевод: единый HTTP-клиент на сессию, создание потока до 8 секунд, бюджет одной попытки финала 10 секунд и черновика 5 секунд. При таймауте, сетевой ошибке или HTTP 5xx финал повторяется один раз через 250 мс; общий максимум 20,25 с. Ошибки параметров/авторизации не повторяются. Между запусками черновиков минимум 750 мс; финал или исправление ASR отменяет устаревший запрос. Совпавший готовый черновик может стать финалом без повторного API-запроса. Фразы сохраняют порядок FIFO. Переполнение очереди явно останавливает распознавание, сохраняя оригинал и ошибку. Максимум 10 000 фраз на сессию; аудиобуфер, контекст и выборки метрик также ограничены.

Runtime публикует монотонную версию. Оба окна сначала подписываются на события, затем получают snapshot, периодически сверяют его и игнорируют старые версии. Перезагрузка WebView не начинает новую сессию и не очищает субтитры.

Текст отправляется целыми словами с интервалом около 80 мс (CJK — по символам). В черновике скрываются последние два слова (CJK: четыре символа). Дополнение показывается сразу; переработанная формулировка заменяет черновик только по завершении ответа. Неудачный финал создаёт помеченный cue с оригиналом; следующий успешный финал очищает предупреждение перевода, сохраняя другие статусы. Оверлей подписан отдельно на текущий текст, статус, оригинал и список cue с постоянными ID. Готовые строки memoized; новый JSON snapshot не меняет ссылки неизменившихся массивов и cue. Polling оверлея 2 секунды — восстановление после пропуска событий, не механизм появления текста.

## Хранение

По умолчанию %APPDATA%\interview-translator:
- config.json — настройки без успешно перенесённых ключей;
- sessions/<id>.json — оригинал, перевод, ошибки и временные отметки;
- app.log — технический журнал без текста разговоров и API-ключей.

Настройки/история записываются через временный файл, sync и rename. Mutex сериализует изменение конфигурации внутри процесса. Геометрия окна сохраняется отдельно от формы, поэтому старая форма не затирает новое положение. Координаты логические, с учётом DPI; положение за пределами доступных мониторов не восстанавливается.

Ключи — Windows Credential Manager, macOS Keychain либо Linux Secret Service. Операции хранилища и перечисление устройств вынесены в blocking workers, чтобы системный запрос доступа не блокировал UI. При неудаче миграции старый ключ остаётся в прежнем конфиге для восстановления; очищается только после успешного сохранения. BABELHACK_DATA_DIR (и прежний INTERVIEW_TRANSLATOR_DATA_DIR) меняет каталог файлов, но не namespace Credential Manager.

История без шифрования, без серверной синхронизации. При выключенном сохранении и в демо запись живёт только в памяти до следующей сессии/выхода. Звук на диск не пишется. Экспорт — явное действие пользователя через нативный диалог TXT/MD/JSON.

## Разработка и проверка

Vite слушает 127.0.0.1:1420; Tauri использует тот же адрес. Артефакты тестов, профили WebView и Rust target исключены из наблюдения. Браузерное демо не имитирует доступ к устройствам или секретам.

Проверки: Rust unit tests, Clippy, TypeScript/Vite, Playwright (включая axe и responsive), опциональные live-тесты синтетического текста/звука, изолированный CDP smoke нативных окон. GitHub Actions настроен на Windows, macOS ARM64/Intel и Linux; локальный прогон выполнен на Windows. На Linux в CI добавлен реальный loopback через виртуальный sink и Secret Service round trip. Результат каждого нативного прогона публикуется в GitHub Actions; CI не заменяет проверку разрешений и устройств на реальном desktop. Инструкции и ограничения — в README.md; результаты аудита — docs/AUDIT.md.

Материалы в docs/legacy описывают прежнюю реализацию и оставлены только как исторический контекст.

## Платформенные детали 0.3

Linux явно выбирает PulseAudio-host и проверяет связь monitor_source_index ↔ monitor_of_sink_index; вход по умолчанию не используется. macOS создаёт process tap независимо от наличия входа у физического устройства, чтобы USB/Bluetooth duplex не переключил захват на микрофон. Tap и aggregate уничтожаются после освобождения стрима даже при ошибках.

Wayland не инициализирует X11 global-hotkey plugin и не запрашивает неподдерживаемую абсолютную позицию. macOS использует непрозрачное окно без private API. Системный Quit, включая Cmd+Q, проходит через ограниченное завершение сессии.

Cargo подключает платформенные keyring features; glib 0.18.5 переопределён локальным security backport для GTK3. Подробности, источники и матрица проверки — docs/PLATFORMS.md.
